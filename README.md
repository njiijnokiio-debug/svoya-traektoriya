# «Своя траектория» — сайт центра речи, развития и семейного образования

Статический сайт на HTML, CSS и JavaScript. Сборка — Node.js без зависимостей и без фреймворков. Все факты о центре собраны в одном файле данных, страницы и служебные файлы генерируются из шаблонов.

## Быстрый старт

Требуется Node.js 18+.

```bash
# пересобрать все страницы, sitemap, robots и manifest
node _tools/build.js

# локальный просмотр (любой статический сервер из корня проекта)
npx serve .
# или
python -m http.server 4173
```

Открывать нужно корень проекта, а не отдельные HTML-файлы: пути к стилям и картинкам рассчитаны на структуру папок.

Для подключения своего домена добавьте файл `CNAME` с доменом в корень репозитория и настройте DNS по инструкции GitHub Pages.

## Где менять контент

### 1. Данные центра

Файл `assets/js/data.js`:

- `brand` — название, телефон, адрес, метро, соцсети, ссылки на карту и маршрут;
- `programs` — 13 программ: название, возраст, формат, расписание, цена, статус набора, SEO-поля, тексты;
- `specialists`, `reviews`, `faq`, `enrollments`, `contacts` — соответствующие разделы.

После правки данных обязательно выполните `node _tools/build.js`.

### 2. Цены и расписание

Цена и признак показа задаются у каждой программы:

```js
price: '1 100 ₽',
priceNote: 'за занятие, абонемент — 4 400 ₽ в месяц',
showPrice: true,
status: 'open',
statusLabel: 'Идёт набор',
```

Если `showPrice: false`, на карточке и странице программы выводится текст из `price` (например, «По запросу» или «После диагностики»). Числовые значения при выключенном показе не публикуются.

### 3. Тексты страниц

- главная — `_tools/page-home.js`;
- о центре — `_tools/page-about.js`;
- каталог и расписание — `_tools/page-catalog.js`;
- страницы программ — `_tools/page-program.js`;
- специалисты, истории, FAQ, контакты, 404 — `_tools/page-misc.js`;
- политика, договор, сведения об организации, админка — `_tools/page-legal.js`;
- общие шапка, подвал, форма, cookie-баннер — `_tools/layout.js`.

## Что нужно заполнить перед публикацией

В коде намеренно оставлены заметные заглушки — их нужно заменить реальными данными:

- [ ] **Домен.** `https://svoya-traektoriya.ru` в `_tools/layout.js` (константа `SITE`), затем пересобрать: canonical, Open Graph, sitemap и robots обновятся.
- [ ] **Цены.** Сейчас известны только четыре программы; у остальных «По запросу». Проверьте актуальность и включите `showPrice` там, где цену можно публиковать.
- [ ] **Расписание.** Время занятий и ближайшие наборы отмечены как «Уточняется».
- [ ] **Специалисты.** Имена, фото, образование и стаж. Сейчас — ролевые карточки с инициалами.
- [ ] **Отзывы.** Реальные истории с согласия родителей. Демонстрационные подписи не выдавайте за реальных людей.
- [ ] **Сведения об организации.** ИНН, ОГРН, юридический адрес, лицензия — в `organization.html` и подвале.
- [ ] **Часы работы, e-mail, мессенджер для заявок.**
- [ ] **Яндекс.Метрика.** Укажите номер счётчика в `<meta name="yandex-metrika-id" content="">` (`_tools/layout.js`) и пересоберите. Счётчик загружается только после согласия на аналитические cookie.
- [ ] **Фотографии.** Замените демонстрационные фото в `assets/img/` на реальные (WebP, при необходимости — с PNG/JPEG-исходником), сохранив имена файлов или обновив ссылки в данных. У каждой картинки должен остаться `alt` и размеры `width`/`height`.
- [ ] **Проверьте тексты на обещания результатов и медицинские формулировки.** Сайт не должен ставить диагнозы и гарантировать результат.

## Формы заявок

Сейчас форма работает в демонстрационном режиме: валидация, маска телефона, защита от спама (скрытое поле), согласие,состояние успеха, сохранение заявки в `localStorage` браузера. На сервер ничего не отправляется.

Для рабочей версии:

1. Добавьте в `initForms()` (`assets/js/site.js`) отправку `fetch` на ваш endpoint после успешной валидации.
2. Настройте приём: e-mail, Telegram-бот, CRM или backend.
3. Перенесите проверки на сервер: обязательные поля, согласие, honeypot, rate limit по IP, защита от повторов.
4. Не храните персональные данные в открытом виде дольше необходимого; журнал согласий обязателен.

Пока endpoint не подключён, не публикуйте сайт как рабочий канал записи: заявки будут видны только в браузере посетителя.

## Демо-панель управления

`admin.html` — интерфейс-прототип без реальной авторизации. Вход по выбору роли, данные хранятся в `localStorage` (`st_admin_data`), есть экспорт/импорт JSON и сброс.

Роли:

- **Владелец** — все разделы;
- **Администратор** — заявки и расписание.

Для продакшена нужен backend или CMS: авторизация с паролем и 2FA, серверные роли, хранение заявок, история изменений, резервные копии. Демо-панель нельзя выкладывать в открытый доступ как есть.

## SEO и аналитика

- У каждой страницы один `H1`, уникальные `title` и `description`, canonical и Open Graph.
- JSON-LD: Organization/LocalBusiness, Course, FAQPage, BreadcrumbList.
- `sitemap.xml`, `robots.txt`, `site.webmanifest`, `favicon.ico`.
- `admin.html` закрыт `noindex` и в robots.
- Метрика подключается только после «Принять аналитические cookie». Выбор «Только необходимые» не загружает счётчик.
- Перед запуском проверьте sitemap после смены домена и отправьте его в Яндекс.Вебмастер и Google Search Console.

## Доступность и адаптивность

- Мобильный приоритет: проверено на 360, 768, 1024 и 1440 px, горизонтальной прокрутки нет.
- Интерактивные элементы — не меньше 44 × 44 px.
- Видимый фокус, поддержка клавиатуры, `aria`-атрибуты, семантические заголовки.
- Контраст текста — WCAG AA; размеры изображений заданы, есть `alt`.
- Меню и фильтры закрываются по Escape, фокус возвращается на кнопку.


Результаты Lighthouse (mobile) на момент сборки: **100 / 100 / 100** по Accessibility, Best Practices и SEO на главной, каталоге, страницах программ, расписании, специалистах, историях, FAQ, контактах, юридических страницах и в демо-админке.

## Публикация

1. Соберите сайт: `node _tools/build.js`.
2. Загрузите на хостинг всё, кроме `_tools/`, `_qa/`, `README.md` и служебного `doc.xml`.
3. Включите HTTPS, сжатие (gzip/brotli) и кэширование статики.
4. Настройте 404 на `404.html`.
5. Замените демонстрационные данные и пройдите чек-лист выше.
6. Проверьте формы на реальном домене и тестовую заявку в приёмнике.

## Технические заметки

- Шрифт Onest подключён локально (`assets/fonts/`), внешние CDN не используются.
- Картинки оптимизированы; для новых фото готовьте WebP/AVIF и указывайте `width`/`height`.
- Сборка перезаписывает HTML-файлы. Правки в сгенерированных страницах будут потеряны — меняйте шаблоны в `_tools/` и данные в `assets/js/data.js`.
- Проект не использует сборщик и package.json: достаточно Node.js и статического хостинга.
